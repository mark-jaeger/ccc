  <name>Task 1: Create zmx package with Session struct and command builders</name>
  <files>zmx/zmx.go, zmx/zmx_test.go</files>
  <behavior>
    - BuildListCommand returns "zmx list"
    - BuildAttachCommand("dev") returns "TERM=$TERM zmx attach dev"
    - BuildCreateCommand("dev", "/home/user/project") returns "cd /home/user/project && TERM=$TERM zmx attach dev"
    - BuildKillCommand("dev") returns "zmx kill dev"
    - BuildCheckCommand returns "command -v zmx"
    - All commands with special chars in names are shell-quoted
  </behavior>
  <action>
Create zmx/zmx.go with:

1. Session struct:
```go
type Session struct {
    Name      string  // session name
    PID       int     // process ID
    Clients   int     // number of attached clients
    StartedIn string  // directory where session started
    Project   string  // extracted project key (from ccc.{project}.{suffix})
    Suffix    string  // extracted suffix
    External  bool    // true if not prefixed with "ccc."
}
```

2. Command builders (all use shellutil.Quote for names/paths):
- `BuildListCommand() string` - returns "zmx list"
- `BuildAttachCommand(name string) string` - returns "TERM=$TERM zmx attach {name}"
- `BuildCreateCommand(name, path string) string` - returns "cd {path} && TERM=$TERM zmx attach {name}"
- `BuildKillCommand(name string) string` - returns "zmx kill {name}"
- `BuildCheckCommand() string` - returns "command -v zmx"

Key differences from abduco:
- zmx uses session NAME for kill (not PID)
- zmx uses TERM=$TERM prefix for attach/create (terminal passthrough per FR-1.5)
- zmx has no detach key config (ctrl+\ is hardcoded in zmx)
- Create and attach are same command (zmx attach creates if not exists)

Create zmx/zmx_test.go with tests for all command builders covering:
- Basic names
- Names with spaces/special characters (verify quoting)
- Paths with spaces (verify quoting)
  </action>
  <verify>
    <automated>go test ./zmx/ -run "TestBuild" -v</automated>
  </verify>
  <done>All Build*Command functions return correctly formatted shell commands</done>
</task>

<task type="auto" tdd="true">
  <name>Task 2: Implement zmx list output parsing</name>
  <files>zmx/zmx.go, zmx/zmx_test.go</files>
  <behavior>
    - ParseListOutput parses "session_name=dev\tpid=1234\tclients=1\tstarted_in=/home/user" into Session
    - Empty input returns nil slice
    - Malformed lines are skipped
    - Session names like "ccc.myproject.main" are parsed into Project="myproject", Suffix="main"
    - Non-ccc sessions are marked External=true
    - FilterSessionsForProject filters by Project field, includes External sessions
    - NextAutoName returns "ccc.{project}.main" for first session, then increments
  </behavior>
  <action>
Add to zmx/zmx.go:

1. `ParseListOutput(output string) []Session`:
   - Parse zmx list output format: tab-separated key=value pairs per line
   - Format: `session_name=<name>\tpid=<pid>\tclients=<count>\tstarted_in=<dir>`
   - Extract all four fields into Session struct
   - Call parseSessionName to populate Project/Suffix/External

2. `parseSessionName(name string) Session` (internal):
   - Pattern: "ccc.{project}.{suffix}"
   - Non-matching → External=true

3. `FilterSessionsForProject(sessions []Session, projectKey string) []Session`:
   - Include sessions where Project == projectKey
   - Also include External sessions (for visibility)

4. `NextAutoName(projectKey string, existing []Session) string`:
   - First session: "ccc.{projectKey}.main"
   - Subsequent: "ccc.{projectKey}.2", "ccc.{projectKey}.3", etc.
   - Same logic as abduco package

Add tests to zmx/zmx_test.go:
- TestParseListOutput with various zmx list outputs
- TestParseSessionName for ccc.project.suffix and external names
- TestFilterSessionsForProject
- TestNextAutoName
  </action>
